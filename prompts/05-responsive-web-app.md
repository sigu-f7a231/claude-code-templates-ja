# レスポンシブ対応の Web アプリケーションを作ってください

## 概要

- アプリの目的: 【誰の、どんな課題を解決するか】
- 主なユーザーと利用シーン: 【例: 現場スタッフがスマホで入力、管理者が PC で集計】
- 端末の比率: 【スマホ ○% / タブレット ○% / PC ○%】

> 機能要件・データ・認証・技術(バックエンド、DB)・非機能要件は、`04-web-app.md` の各項目をこの下に追記してください。

## レスポンシブ要件

- 対応する画面幅(ブレークポイント): 【例: スマホ 〜767px / タブレット 768〜1023px / PC 1024px〜】
- 方針: **モバイルファースト**(スマホで設計し、広い画面で拡張する)
- 対応ブラウザ: 【例: iOS Safari / Android Chrome / 最新の PC ブラウザ】
- 向き: 【縦のみ / 縦横対応】

## 画面ごとのレイアウト指定

| 画面 | スマホ | タブレット | PC |
|---|---|---|---|
| 【ナビゲーション】 | 【ハンバーガー or 下部タブ】 | 【サイドバー(折りたたみ)】 | 【固定サイドバー】 |
| 【一覧】 | 【カード表示(1 列)】 | 【2 列】 | 【テーブル表示】 |
| 【フォーム】 | 【1 列、大きな入力欄】 | 【1 列】 | 【2 列】 |
| 【詳細】 | 【縦積み】 | 【縦積み】 | 【左右 2 カラム】 |

## タッチ・操作性

- タップ領域は十分に大きく(目安 44×44px 以上)、隣接するボタンの間隔を確保
- ホバーに頼る操作を作らない(スマホで使えないため)
- 入力欄は種類に合わせたキーボード(`type="email"` `inputmode="numeric"` など)
- 片手操作を想定し、主要な操作を画面の下側に置くことを検討
- 画像は `srcset` やサイズ指定で最適化。レイアウトのずれ(CLS)を防ぐ

## 通信・オフライン

- スマホ回線を想定し、初回読み込みのサイズを抑える(遅延読み込み・コード分割)
- 通信失敗時のメッセージと再試行を用意
- PWA 対応: 【する / しない】(する場合: ホーム画面に追加、オフライン時の表示範囲、更新の通知)

## 技術

- フロントエンド: 【React / Next.js / Vue など。未定なら提案】
- CSS: 【Tailwind / CSS Modules / UI ライブラリ】(メディアクエリ or コンテナクエリでレイアウトを切替)
- 固定ピクセル幅に依存しない(相対単位 `rem` `%` `fr`、`clamp()` などを使う)

## 品質要件

- 実機に近い確認: ブラウザの開発者ツールで 375px(スマホ)、768px(タブレット)、1280px(PC)を確認
- アクセシビリティ: 文字の拡大、コントラスト、スクリーンリーダー向けのラベル
- 性能: モバイルでの表示速度(Lighthouse などで計測し、結果を報告)

## 完了条件

- [ ] 3 種類の画面幅で、全画面が崩れず、横スクロールが出ない
- [ ] スマホでタップしにくい箇所がない
- [ ] 主要な操作がスマホだけで完結する
- [ ] 通信エラー時の表示が確認できる
- [ ] `04-web-app.md` の完了条件も満たす

## 進め方

1. まず「画面一覧とブレークポイントごとのレイアウト案(簡単な文章または ASCII 図)」を提示して承認を待ってください。
2. 承認後、共通レイアウト(ナビ・グリッド)→ 各画面の順に、**スマホ幅から**実装してください。
3. 各ステップで、幅ごとの確認方法を示してください。
