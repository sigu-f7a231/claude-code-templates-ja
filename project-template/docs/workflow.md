このプロジェクトの作業の進め方をまとめる。人も Claude も、この順で進める。

## 1. 全体の流れ

```text
① 計画を作る                 ② 1タスクずつ進める                  ③ 公開する
/spec → /plan-tasks   →   ( /implement → /test → /review → /commit )×タスク数   →   /release
   ↓          ↓                       ↑ 次のタスクへ戻る
spec.md    plan.md(タスクが溜まる)
        ↑ 承認
```

- 指示を出すところからの手順は 雛形集の `read/13-from-instruction-to-release.md` を参照。
- 計画(`docs/plan.md`)にタスクを溜め、**どれをやるかは人が `/implement <番号>` で指示する**。
- 各工程の終わりに Claude が報告して止まる。**次へ進むかは人が決める**。
- 仕様が変わるときは、先に `docs/spec.md` を更新してから、計画と実装に反映する。

## 2. 工程ごとの手順

> 各コマンドの日本語での意味と、`/implement 3` の「3」(`docs/plan.md` のタスク番号)の見方は、雛形集の `read/13-from-instruction-to-release.md` の「コマンド早見表」にあります。

| 工程 | 呼び出し | 入力 | 出力 | 人がやること |
|---|---|---|---|---|
| 要件整理 | `/spec <概要>` | 目的・概要 | `docs/spec.md` | 質問に答え、内容を確認・修正する |
| 計画 | `/plan-tasks <機能>` | `docs/spec.md` | `docs/plan.md` | タスクの分け方・順序を確認して**承認**する |
| 実装 | `/implement <番号>` | `docs/plan.md` のタスク | コード、テスト、plan の更新 | 報告(変更ファイル・結果)を読む |
| テスト | `/test [対象]` | 変更したコード | テスト結果、修正 | 失敗の原因と修正内容を確認する |
| レビュー | `/review` | 差分 | 指摘の一覧(読み取りのみ) | 指摘のうち対応するものを決める |
| コミット | `/commit` | 差分 | コミット | メッセージと内容を確認する |
| リリース準備 | `/release <版>` | 全体 | チェック結果、リリースノート案 | 公開操作(push・デプロイ)を**自分で**行う |

## 3. 1タスクのサイクル

```text
/implement 3          # 計画のタスク3を実装
   ↓ 報告を確認
/test                 # テストと lint
   ↓ 失敗があれば修正してから
/review               # 差分をレビュー(別コンテキスト・読み取り専用)
   ↓ 重要な指摘を修正 → 再度 /test
/commit               # 1つの目的にまとめてコミット
   ↓
/implement 4          # 次のタスクへ
```

- 小さな修正は、Skills を使わず通常の依頼でよい(実装後に `/test` を実行する)。
- 調査や長いテスト出力は、Subagent に任せられる(`researcher`、`test-runner`)。

## 4. 誰が何を動かすか

| 動かすもの | きっかけ | このプロジェクトでの例 |
|---|---|---|
| Skills(`/名前`) | **人が呼ぶ** | `/implement 3`、`/commit` |
| `docs/plan.md` | 動かない。状態を持つファイル | 次にやるタスクの一覧。完了すると `[x]` になる |
| Rules | **自動**(対象ファイルを触ったとき) | `docs/**` の書き方、テストの書き方 |
| Hooks | **自動**(イベント) | `git push` のブロック、再開時の進捗表示 |
| 権限設定 | **自動** | テスト・git の読み取りは許可、`push` や `.env` は拒否 |
| CLAUDE.md | **自動**(毎回) | 概要、ワークフロー(Skills)、ドキュメントの置き場所 |
| Rules(パスなし) | **自動**(毎回) | 技術スタック、コマンド、作業ルール、注意事項 |
| Subagents | 人が頼む / Claude が委任 | 調査、テスト実行 |

## 5. ファイルとその役割

| ファイル | 役割 | 更新するとき |
|---|---|---|
| `CLAUDE.md` | 概要・ワークフロー・ドキュメントの置き場所 | 進め方や構成が変わったとき |
| `.claude/rules/commands.md` | よく使うコマンド(Skills が参照) | コマンドが変わったとき |
| `.claude/rules/tech-stack.md` `code-style.md` `work-rules.md` `cautions.md` | 技術スタック・コード規約・作業ルール・注意事項 | 該当の内容が変わったとき(技術変更は先にここを更新) |
| `docs/spec.md` | 何を作るか(要件・完了条件) | 仕様が変わったとき(**先に**更新) |
| `docs/plan.md` | どう進めるか(タスクと進捗) | `/plan-tasks` で作成、`/implement` で更新 |
| `docs/workflow.md`(このファイル) | 作業の進め方 | 進め方を変えたとき |
| `.claude/skills/` | 工程別の手順 | 工程を足す・直すとき |
| `.claude/rules/` | ファイル別の規約 | 同じ指摘を繰り返したとき |
| `.claude/hooks/`、`.claude/settings.json` | 自動での制限・通知、権限 | 禁止したいことが増えたとき |

## 6. ルール

- **1回の `/implement` で、1タスクだけ**進める。範囲外の改善はしない(気づいた点は報告に書く)。
- **仕様にない機能は追加しない。** 必要なら、先に `docs/spec.md` を更新する。
- **コミット前に、テストと lint を通す。**
- **`git push`、デプロイ、ストア申請は人が行う。** Claude は実行しない(Hooks と権限設定でも止める)。
- **既存ファイルの削除、依存パッケージの追加、設定ファイルの大きな変更は、実行前に確認する。**
- **秘密情報**(キー、パスワード、`.env`)は、コードに書かず、コミットしない。

## 7. 会話が切れたとき・迷ったとき

| 状況 | 対処 |
|---|---|
| 会話が圧縮・再開された | `SessionStart` のフックが未完了タスクを表示する。`/implement <番号>` で続ける |
| 現在地が分からない | 「`docs/plan.md` と `git log` を見て、現在地と次のタスクを教えて」と頼む |
| 計画と違う方向に進んでいる | 止めて、`docs/plan.md` を見直す。必要なら `/plan-tasks` で計画を更新する |
| 仕様が変わった | `docs/spec.md` を更新 → `/plan-tasks` で計画に反映 → 該当タスクから再開 |
| テストが通らない | `/test` で原因を調べる。仕様の問題なら、修正せず報告させる |
| スキルが一覧に出ない | `.claude/skills/<name>/SKILL.md` の場所を確認。`/reload-skills` か再起動 |

- [ ] `docs/spec.md` の完了条件が、すべて満たされている
