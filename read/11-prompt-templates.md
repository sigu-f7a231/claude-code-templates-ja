# 開発の指示テンプレート(最初の指示 + 種類別)

テンプレート本体: [`../prompts/`](../prompts/README.md)
Claude Code に最初に渡す「指示依頼文(プロンプト)」のひな形です。`【 】` を埋めて貼り付けて使います。

## 一覧

| ファイル | 種類 | 向いているもの |
|---|---|---|
| [`00-first-instruction.md`](../prompts/00-first-instruction.md) | **最初の指示(共通)** | どの種類でも最初に使う。質問 → 計画 → 承認 → 実装の流れを伝える |
| [`01-static-page.md`](../prompts/01-static-page.md) | 静的ページ | 1〜数ページの HTML/CSS。ビルド・サーバー不要 |
| [`02-landing-page.md`](../prompts/02-landing-page.md) | LP | 1つの目的(申込・問い合わせ等)に絞った縦長 1 ページ |
| [`03-homepage.md`](../prompts/03-homepage.md) | HP | 会社・店舗の複数ページのサイト(更新・運用あり) |
| [`04-web-app.md`](../prompts/04-web-app.md) | Web アプリ | ログイン・データ操作を伴う業務/サービス系 |
| [`05-responsive-web-app.md`](../prompts/05-responsive-web-app.md) | レスポンシブ Web アプリ | PC・タブレット・スマホ全対応(PWA も可) |
| [`06-mobile-app-flutter.md`](../prompts/06-mobile-app-flutter.md) | スマホアプリ(Dart/Flutter) | 1つのコードで iOS と Android |
| [`07-native-app.md`](../prompts/07-native-app.md) | ネイティブアプリ | iOS(Swift)/ Android(Kotlin)の OS 専用 |

## 種類の選び方

| 状況 | 選ぶもの |
|---|---|
| 数ページで、更新も少ない | 静的ページ |
| 1つの行動(申込など)につなげたい | LP |
| 組織・店舗の情報を継続的に発信 | HP |
| ログイン・データの登録や管理が必要 | Web アプリ |
| スマホからの利用が主で、ストア配布は不要 | レスポンシブ Web アプリ(PWA) |
| ストア配布が必要で、iOS/Android を同時に作りたい | スマホアプリ(Flutter) |
| OS 固有機能を深く使う・OS 標準の作法に合わせたい | ネイティブアプリ |

## 使い方(手順)

1. **種類を決める。** 上の表で選ぶ。
2. **`00-first-instruction.md` を埋めて貼り付ける。** まず質問と計画だけをさせ、実装はまだ始めさせない。
3. **種類別テンプレートを埋めて続けて貼り付ける。** 決まっていない項目は「未定。提案してほしい」と書く(空欄にしない)。
4. **計画を読んで承認(または修正)する。** プランモード(`Shift+Tab` で切替)なら、承認前にファイルは変更されない。
5. **`/init` で CLAUDE.md を作る。** 合意した技術・コマンド・規約を記録する(`02-claude-md.md` 参照)。
6. **小さなステップごとに確認しながら進める。** 繰り返す指示は Rules / Skills へ、必ず守らせたいことは Hooks / permissions へ移す。

## テンプレートに共通する構成

| 項目 | 目的 |
|---|---|
| 概要・目的 | 何を、誰のために作るか。完成の定義を共有する |
| 要件(機能・内容) | 作る範囲を明確にする |
| 技術 | 使う/使わないものを決める(未定なら提案を求める) |
| デザイン | 雰囲気・配色・参考例を伝える |
| 品質要件 | セキュリティ、SEO、アクセシビリティ、性能など |
| 完了条件(チェックリスト) | 「できた」の基準を検証可能にする |
| 進め方 | 計画 → 承認 → 小さく実装 → 確認、の順を指定する |

## 書き方のコツ

- **検証できる形で書く。** 「見やすく」ではなく「スマホ幅 375px で横スクロールが出ない」。
- **範囲を絞る。** 最初は必須機能(MVP)だけを頼み、後回しは明記する。
- **決まっていないことは、決めてほしいと頼む。** 「2案を比較して提案して」と書く。
- **やってほしくないことも書く。** 例: 「有料サービスは使わない」「既存ファイルは確認なしに削除しない」。
- **自分がやる作業を明示してもらう。** 実機確認、アカウント登録、証明書、ストア操作など。

## 配置場所(使うときに、どこに置くか)

指示文のテンプレートは、**Claude Code に貼り付けて使うもの**で、プロジェクトの設定ファイルではありません。置き場所は次のとおりです。

| 使い方 | 置く場所 | 備考 |
|---|---|---|
| そのまま貼る(最初の指示など) | 置かない(Claude Code のプロンプトに貼る) | 雛形(`../prompts/`)を開いて、埋めて貼る |
| 埋めた指示を、後で見返せるように残す | `<プロジェクト>/docs/brief.md` など | 会話が新しくなると、前の指示は Claude から見えなくなるため。`/spec docs/brief.md` のように渡せる |
| `/spec` に渡すアイデアメモ | `<プロジェクト>/docs/idea.md` | ひな形は `../prompts/11-spec-input.md` |
| 繰り返し使う指示 | Skills(`.claude/skills/`)にする | 毎回貼る手間が減る(`04-skills.md`) |
| 毎回の前提になる内容 | Rules(`.claude/rules/`)にする | 指示ではなく、前提として常に読み込まれる(`03-rules.md`) |

- 雛形そのもの(`../prompts/`)は、**雛形集に置いたまま**使います。自分のプロジェクトにコピーするのは、埋めた結果(`docs/brief.md` など)だけです。
- 秘密情報(キー、パスワード)は、指示文にも `docs/` にも書かないでください。

## 注意

- これらのテンプレートは、公式ドキュメントの内容ではなく、一般的な開発の進め方をもとに私が作成した例です。プロジェクトに合わせて項目を足し引きしてください。
- ツールのバージョンや仕様(Flutter、Xcode、Android Studio、各ストアの審査基準など)は変わるため、最新の公式情報を確認してください。
- 実装系のテンプレートで挙げた技術名(React、Riverpod、Room など)は例です。指定しなければ、Claude に提案させられます。
