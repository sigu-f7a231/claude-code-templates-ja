## 変更の状況

- 変更ファイル: !`git status --short`
- 差分: !`git diff HEAD`

## あなたの仕事

上の差分をレビューしてください。ファイルは変更しません(読み取りのみ)。必要なら周辺のコードも読んで、整合性を確認してください。

## 観点

1. バグの可能性(境界値、null、競合、エラー処理の漏れ)
2. セキュリティ(入力検証、認証・権限、秘密情報、インジェクション)
3. 仕様との一致(`docs/spec.md` があれば照合)
4. 可読性・命名・重複
5. テストの不足

## 出力形式

重要度(高 / 中 / 低)の順に、箇条書きで報告してください。各指摘には次を含めます。

- ファイル名と行番号
- 問題点(なぜ問題か)
- 改善案

問題がなければ、「重大な問題は見つかりませんでした」と報告し、確認した観点を1行で示してください。
