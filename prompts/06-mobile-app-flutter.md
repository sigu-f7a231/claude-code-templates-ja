# スマホアプリ(Flutter / Dart)を作ってください

## 概要

- アプリの目的: 【誰の、どんな課題を解決するか】
- 対象 OS: 【iOS / Android / 両方】(最低バージョン: 【例: iOS 15 / Android 8】)
- 配布: 【個人利用 / 社内配布 / ストア公開】
- 想定する使い方: 【例: 片手、移動中、通信が不安定】

## 開発環境(最初に確認してください)

- Flutter / Dart の導入状況: 【導入済み / 未導入(手順を案内してほしい)】
- 実機・エミュレーター: 【iOS シミュレーター / Android エミュレーター / 実機】
- `flutter doctor` の結果を確認し、足りないものがあれば案内してください
- Mac 以外の環境では iOS ビルドができない点を考慮

## 機能要件

| 機能 | 内容 | 優先度 |
|---|---|---|
| 【ログイン】 | 【方式】 | 【必須】 |
| 【一覧・詳細】 | 【内容】 | 【必須】 |
| 【入力・保存】 | 【内容】 | 【必須】 |
| 【プッシュ通知】 | 【内容】 | 【後回し】 |

## 画面と操作

- 画面一覧と遷移: 【例: スプラッシュ → ログイン → ホーム(タブ: 一覧 / 設定)→ 詳細】
- デザイン: 【Material 3 / Cupertino(iOS 風)/ 独自】。ダークモード: 【対応する / しない】
- タブレット・横向き: 【対応する / しない】
- 参考アプリ・デザイン案: 【URL / 画像】

## データ・通信

- データの保存: 【端末内(SQLite, shared_preferences など)/ サーバー(REST API, Firebase など)/ 未定】
- API: 【仕様書の場所 / これから設計】
- オフライン動作: 【必要 / 不要】(必要な場合の同期方針)
- 端末の権限: 【カメラ / 位置情報 / 通知 / 写真 など。必要な理由を明記】

## 技術方針

- 状態管理: 【Riverpod / Bloc / Provider / 未定(提案してほしい)】
- ナビゲーション: 【go_router など / 未定】
- アーキテクチャ: 画面(UI)・状態管理・データ層(リポジトリ)を分ける
- パッケージ: 追加する場合は、用途・メンテ状況・ライセンスを確認してから `pubspec.yaml` に追加する
- 静的解析: `flutter analyze` の警告をゼロにする。`dart format` で整形する
- 秘密情報: キーをソースに直書きしない(`--dart-define` や環境ごとの設定を使う)

## 品質要件

- テスト: ユニットテスト(ロジック)、ウィジェットテスト(主要画面)
- 日本語対応: 文言は直書きせず、ローカライズの仕組み(`intl` など)を検討
- アクセシビリティ: 文字サイズ拡大、タップ領域、コントラスト
- 性能: スクロールのなめらかさ、起動時間、メモリ使用量

## 完了条件

- [ ] 必須機能が、対象 OS のエミュレーター/実機で動作する
- [ ] `flutter analyze` と `flutter test` が通る
- [ ] 画面サイズ(小型スマホ・大型スマホ)で崩れない
- [ ] 権限の拒否・通信失敗・空データの表示が確認できる
- [ ] 起動手順とビルド手順が `README` にある
- [ ] (ストア公開の場合)アプリ名・アイコン・スプラッシュ・署名設定・プライバシー情報が整理されている

## 進め方

1. まず「環境確認 → 要件の質問 → 画面遷移図 → 状態管理・データ層の方針 → 作業ステップ」を提示して承認を待ってください。
2. 承認後、`flutter create` でプロジェクトを作り、**1 画面ずつ**(UI → 状態管理 → データ → テスト)実装してください。
3. 各ステップで、実行コマンド(`flutter run -d <device>`)とテスト結果を示してください。
4. 実機やストア操作など、私が行う必要がある作業は、手順を明示してください。
