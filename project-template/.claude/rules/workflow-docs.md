# docs の書き方

## docs/spec.md

- 見出しの順: 目的と背景 / 対象ユーザー / 機能要件 / 非機能要件 / 完了条件 / 未決事項
- 機能要件は「必須」「あると良い」「今回やらないこと」に分ける
- 回答がなく推測で埋めた項目には「【仮定】」を付け、未決事項にも載せる(事実と区別する)
- 完了条件はチェックリスト(`- [ ]`)で、検証できる形で書く
  - ○「スマホ幅 375px で横スクロールが出ない」 / ×「見やすい」

## docs/plan.md

- タスクは番号を振り、1タスク=1つの検証可能な変更にする
- 各タスクに「変更予定のファイル」「確認方法」「依存するタスク」を書く
- 完了したタスクは `- [x]` にして、日付と一言メモを残す
- 仕様を変える必要が出たら、plan.md ではなく先に spec.md を更新する

## 共通

- 推測で書かず、未確認のことは「未確認」と明記する
- 日付は `YYYY-MM-DD` 形式
