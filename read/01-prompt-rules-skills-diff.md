# プロンプト・Rules・Skills の違い

出典: 公式ドキュメント [Skills](https://code.claude.com/docs/en/skills) / [Memory (CLAUDE.md・rules)](https://code.claude.com/docs/en/memory) をもとに整理(2026-11-19 時点)。
関連ファイル: `04-skills.md` / `03-rules.md`

## 一言でいうと

| | 指示依頼文(プロンプト) | Rules(CLAUDE.md / `.claude/rules/`) | Skills |
|---|---|---|---|
| 役割 | 今回やってほしいこと | 常に守ってほしい前提・規約 | 繰り返す手順・専門知識のパッケージ |
| 例 | 「このバグを直して」 | 「インデントは2スペース」「コミット前に `npm test`」 | 「PRを要約する手順」「デプロイ手順」 |
| 保存 | されない(その会話のみ) | ファイル(Gitで共有可) | ファイル(`SKILL.md` + 補助ファイル) |
| 読み込み | 送信したとき | 起動時に常時(`paths` 付きは該当ファイルを触ったときだけ) | 説明文だけ常駐し、本文は使うときだけ |
| 起動方法 | 自分で入力 | 自動(何もしなくても適用) | `/skill-name` で手動、または Claude が自動判断 |
| 引数 | 文中に直接書く | なし | `$ARGUMENTS` などで受け取れる |
| 実行機能 | なし | なし(指示のみ) | シェル実行、サブエージェント、ツール事前許可、フックなど |

## それぞれの使い分け

### 指示依頼文(プロンプト)

- 一度きりの依頼、またはその場の文脈に依存する依頼に使う。
- 会話が終わると消える。`/clear` や `/compact` の後に残らないため、毎回言うことになるなら Rules か Skills に移すサイン。

### Rules

- 「いつも前提にしてほしいこと」を書く。コーディング規約、ビルド・テストコマンド、ディレクトリ構成など。
- Claude への「コンテキスト」であり、強制ではない。公式も「必ず止めたいことはフックや `permissions.deny` を使う」としている。
- 1ファイル200行未満が目安。長いほど遵守率が下がる。
- `.claude/rules/` に `paths` を書くと、特定ファイル(例: `src/api/**/*.ts`)を触るときだけ読み込める。

### Skills

- 「毎回同じ手順を踏む作業」や「長い専門知識」をまとめる。デプロイ、コミット、PR要約、調査など。
- 本文は使われるまで読み込まれないため、コンテキストを節約できる。
- 引数を受け取れ(`/fix-issue 123`)、`!` で実行結果を埋め込め、`context: fork` で別のサブエージェントとして動かせる。
- 副作用のある作業(デプロイなど)は `disable-model-invocation: true` にして手動実行のみにする。

## 判断の目安

1. その場限りか → **プロンプト**
2. 毎回の前提・規約か → **Rules**(全体なら CLAUDE.md、特定ファイル向けなら `paths` 付きルール)
3. 手順やワークフローで、必要なときだけ呼びたいか → **Skills**
4. 例外なく強制したいか → **Rules ではなくフック / `permissions`**

## 具体例

| やりたいこと | 向いているもの |
|---|---|
| 「テストは Arrange/Act/Assert で書く」 | Rules(`paths: **/*.test.ts`) |
| `/release 1.2.0` でテスト→ビルド→タグ付け | Skills |
| 「今日はこのエラーの原因を調べて」 | プロンプト |
| `main` への直接 push を禁止したい | フック / `permissions.deny` |

## 補足

- 従来の `.claude/commands/` は Skills に統合済み(引き続き動作する)。
- Rules に書いた長い手順が増えてきたら、Skills への切り出しが公式の推奨(「複数ステップの手順は skill かパス限定ルールへ」)。
- 3つは併用できる。Rules で規約を常時適用し、Skills で手順を呼び出し、プロンプトで今回の目的を伝える。

## 備考

「プロンプトとの比較」の部分は、公式ドキュメントの記述(Rules / Skills の読み込み方・保存先・起動方法)をもとに筆者が整理したもので、公式に同名の比較表があるわけではありません。
