# テスト規約

- Arrange(準備)/ Act(実行)/ Assert(検証)の順で書く
- 1テスト1つの振る舞いを確認する。テスト名で「何を、どうなるか」が分かるようにする
- 外部 API・時刻・乱数など、不安定なものだけをモックする(それ以外は実物を使う)
- 正常系だけでなく、境界値・空・異常系を最低1つずつ入れる
- 失敗するテストを削除・スキップして通さない。やむを得ない場合は理由をコメントで残す
- バグ修正では、先にそのバグを再現するテストを書く
