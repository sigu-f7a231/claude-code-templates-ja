# Web アプリケーションを作ってください

## 概要

- アプリの目的: 【誰の、どんな課題を解決するか】
- 主なユーザー: 【種類(例: 管理者 / 一般ユーザー)と人数規模】
- 利用環境: 【社内 / 一般公開】【主に PC】

## 機能要件

<!-- 優先度: 必須(MVP)/ あると良い / 後回し -->
| 機能 | 内容 | 優先度 |
|---|---|---|
| 【ユーザー登録・ログイン】 | 【メール + パスワード など】 | 【必須】 |
| 【○○の一覧】 | 【検索・並び替え・ページ分け】 | 【必須】 |
| 【○○の登録・編集・削除】 | 【入力項目、バリデーション】 | 【必須】 |
| 【通知・メール】 | 【内容】 | 【後回し】 |

## データ

- 扱うデータ(エンティティ)と主な項目:
  - 【例: ユーザー(id, 名前, メール, 権限)】
  - 【例: 注文(id, ユーザー, 状態, 金額, 作成日時)】
- データ量の目安: 【例: 数千件】
- 個人情報・機密情報: 【ある / ない。ある場合は種類】

## 認証・権限

- 認証方式: 【メール + パスワード / ソーシャルログイン / SSO / 未定(提案してほしい)】
- 権限: 【ロールごとにできること(例: 管理者のみ削除可)】
- パスワードは必ずハッシュ化して保存し、平文で扱わない

## 技術

- フロントエンド: 【例: React / Next.js / Vue / 未定】
- バックエンド: 【例: Node.js / Python(FastAPI, Django)/ Next.js API / 未定】
- データベース: 【例: PostgreSQL / SQLite / 未定】
- 認証・ホスティング: 【例: 自前 / Auth サービス / Vercel / 未定】
- 提案が必要なら、規模・保守性・学習コストを踏まえて 2 案比較してください
- 言語・型: 【TypeScript を使う / 使わない】

## 非機能要件

- セキュリティ: 入力検証、SQL インジェクション・XSS・CSRF 対策、秘密情報は環境変数、権限チェックはサーバー側で行う
- エラー処理: ユーザー向けのメッセージ、ログには個人情報を出さない
- テスト: 【ユニットテスト / E2E を重要機能に】
- 性能: 【例: 一覧表示は 1 秒以内】
- 運用: 【バックアップ、ログ、監視】

## 画面

- 画面一覧: 【ログイン、ダッシュボード、一覧、詳細、編集 など】
- デザイン: 【既存のデザインシステム / UI ライブラリ(例: shadcn/ui, MUI)/ シンプルで OK】

## 完了条件

- [ ] 必須機能がすべて動作する(正常系・異常系)
- [ ] 権限のないユーザーが操作・閲覧できない
- [ ] テストが通り、`README` にセットアップ手順(環境変数、DB 初期化、起動コマンド)がある
- [ ] `.env` はコミットされず、`.env.example` がある

## 進め方

1. まず「要件の確認質問 → データモデル案 → API/画面の一覧 → 技術提案 → 作業ステップ」を出して承認を待ってください。
2. 承認後、**縦に薄く(1 機能ずつ、DB → API → 画面 → テスト)**実装してください。
3. 各ステップで、動作確認のコマンドとテスト結果を示してください。
4. DB のスキーマ変更はマイグレーションで管理し、既存データを壊す操作は事前に確認してください。
